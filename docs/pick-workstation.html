Shoddy · Picker

The Picked Workstation

Two pictures: the server as a map with one database lit, and the boundaries that make it look that way. There is less to draw than on the fettled workstation, because SQL needs less. One database, one statement, no shell.

← PreviousPickerQuick StartNext →

fettle's map is a whole disk: directories, scratch folders, credentials, an operating system, and every way off the machine. pick's world is one server, one declared database, and one way in. No command produced this arrangement. Every line of it was written by hand into .picker.json and its uncommitted local twin. Both are printed on the project page, and pick refuses to write either.

The server, and the one way onto it

Matching the map to the two files that drew it:

the one way inthe connect line in the uncommitted local file, and the gate in front of it, which no line switches off

And here is how it is held

How to read it

  • The model boundary needs nothing new. The eleven built-ins a fettled workstation denies are file tools, shells and output readers. None of them speaks SQL. Registering pick is one .mcp.json entry, and pick refuses to write that file, or any file that governs it or the model.
  • The tool boundary is a governed file, re-read every call. fettle serve learns its trees at launch. pick re-reads .picker.json before every call, so an edit binds on the next request. No tool schema carries a connection string or a database name to widen it with. And where fettle must refuse its write verbs on governed files, pick is simpler still: it has no write verb at all.
  • The server boundary is the declared databases. No default database, no USE, no sys.*, no linked servers. Objects and columns are scoped one by one, and hidden is refused in the words of absent. The reference holds every refusal.
  • And beneath all of it, the login, granted only SELECT and VIEW DEFINITION, so the server keeps its own boundary too. The login argument in full.

Prove it. Do not trust it. Ask the assistant to try each of these, and watch what comes back:

Ask it to…A correct setup…
select from a database on the server that is not declaredrefuses as not found, in the same words as a table that never existed
