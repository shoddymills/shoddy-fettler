Shoddy · Picker

Quick Start

Install it, point it at a server, declare one database, check it, refuse something. Five steps, and the refusals are the part worth watching.

← PreviousThe Picked WorkstationInstalling ItNext →
You need two things before you start: the pick archive for your platform from the latest release, and a SQL Server with a database in it — and if you have neither server nor database, step 2 conjures both from nothing on a Windows machine. Everything else is below.

1. Install it

One file. No .NET runtime, no installer. X.Y.Z is whatever version you downloaded.

Windows · PowerShell
$dir = "$env:LOCALAPPDATA\Programs\pick"
New-Item -ItemType Directory -Force $dir | Out-Null
Expand-Archive pick-X.Y.Z-win-x64.zip -DestinationPath $dir -Force
Get-ChildItem $dir -Recurse | Unblock-File
$user = [Environment]::GetEnvironmentVariable('Path', 'User')
if ($user -notlike "*$dir*") {
    [Environment]::SetEnvironmentVariable('Path', "$user;$dir", 'User')
}
macOS and Linux
mkdir -p ~/.local/bin
tar -xzf pick-X.Y.Z-osx-arm64.tar.gz -C ~/.local/bin
xattr -d com.apple.quarantine ~/.local/bin/pick   # macOS only

Open a new terminal — the one you just used still has the old PATH — then check it:

pick version
If that says not recognised or command not found, open a new terminal first, then re-check the directory. Nothing later on this page works until this line does. Putting it on PATH is the long version.

2. Have a server

Any SQL Server you can already reach works — skip to step 3 with its connection string, ideally for a login granted only SELECT and VIEW DEFINITION. With nothing at hand, LocalDB is the zero-install instance on a Windows development machine:

sqllocaldb start MSSQLLocalDB

If sqllocaldb is not a command, install SQL Server Express LocalDB (the SqlLocalDB.msi from the SQL Server Express installer's Download Media option) and run it again. And if there is no database worth pointing at yet, make a toy one:

sqlcmd -S "(localdb)\MSSQLLocalDB" -E -Q "CREATE DATABASE Sales;"
sqlcmd -S "(localdb)\MSSQLLocalDB" -E -d Sales -Q "CREATE TABLE dbo.Customers(id int PRIMARY KEY, name nvarchar(80)); INSERT dbo.Customers VALUES (1, N'Iris Sutcliffe'), (2, N'Harold Wilson');"

3. Declare the boundary — two short files

In the project directory, the checked-in surface:

// .picker.json
{
  "servers": {
    "local": {
      "databases": {
        "Sales": { "can": ["list", "select", "describe"] }
      }
    }
  }
}

And beside it, kept out of source control, the connection:

// .picker.local.json
{
  "servers": {
    "local": {
      "connect": "Server=(localdb)\\MSSQLLocalDB;Integrated Security=true;TrustServerCertificate=true"
    }
  }
}
A password literal in the checked-in file refuses the whole load, with directions — credentials go in the local file or an env:NAME variable. The reviewed file is the one that ends up in source control and in every copy of the project.

Then check the wiring — the configuration, a bounded knock on the server, and the screening pieces if any:

pick doctor
pick catalogs    # the boundary you just declared - no connection opened
pick objects     # the tables and views you may actually see

4. The first SELECT — and the first refusals

pick select "SELECT TOP 5 * FROM Customers"
pick describe Sales.dbo.Customers

An unqualified name is resolved against the declared databases — never against a default the connection happens to be sitting in. Now watch it refuse, because the refusals are the feature:

CommandExitBecause
pick select "DELETE FROM Customers"8not a SELECT — there is no write verb anywhere in pick
pick select "SELECT 1; SELECT 2"8one statement per call, parsed whole
pick select "SELECT name FROM sys.tables"8the catalog is closed; describe answers instead, governed by the scopes
pick select "SELECT * FROM master.dbo.spt_values"3an undeclared database — refused in the same words as a table that never existed

That last one in full, because the wording is the point:

not-found: there is no table or view called 'master.dbo.spt_values' inside the
declared databases; the objects tool lists what is here

master is real and inches away. The refusal does not know that, and neither can anyone reading refusals.

5. Wire it into the assistant

One entry in the project's .mcp.json, written by hand — and nothing else changes, because the client has no built-in SQL tool to deny:

{
  "mcpServers": {
    "picker": { "command": "pick", "args": ["serve"] }
  }
}

Then restart the assistant — a client reads its server list at launch — and ask it what it can see. catalogs answers with the boundary; everything outside it answers as if it were not there. A changed .picker.json needs no restart at all: the server re-reads it before every call.

6. Turn the screen on (optional, one line)

"Sales": { "can": ["list", "select", "describe"], "screen": ["identifiers"] }

From the next call, a result set carrying an SSN, a Luhn-valid card, an email, a phone number, or a labelled record number or date of birth refuses whole — naming a category and a count, and quoting nothing back. Screening, for the rows proves each edge with synthetic data.
