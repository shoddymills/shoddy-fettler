**File, search and edit tools for a model and a script. One program, two
front ends, no shell between it and the file.**

`fettle` is a bounded workbench over a set of trees a person declares. It
reads, searches and edits files; it reads notebooks, PDFs, spreadsheets, Word
documents, images and archives; it refuses anything outside the boundary, and
it says why. `burler` is its optional sidecar, hosting the models the
disclosure screen's second tier needs.

## What it does

| | |
|---|---|
| **A boundary, not a suggestion** | Every path resolves inside a declared tree. Outside is refused identically whether or not the file exists, so a refusal cannot be used to probe a disk. There is no current directory to change and no shell to reach past it with. |
| **Two front ends, one core** | A CLI for a script and an MCP server for a model, over the same operations. Machine-readable mode puts the complete result on stdout, failures included. |
| **It reads more than source** | Notebooks as cells, spreadsheets as rows with their formulas, Word as paragraphs under their headings, PDF as text per page, images as facts — and inside archives without unpacking them. |
| **Batches are all or nothing** | Every edit resolves before the first byte moves. A permission the tree does not grant, a file that changed underneath, an anchor that no longer matches: any of these stops the whole batch with the tree exactly as it was. |
| **A disclosure screen, off by default** | A tree can declare that regulated data must not leave it. Anything the screen cannot see into is refused rather than served unchecked. |
| **Declared tasks, never a composed command** | `run` takes a task name and a timeout. What it executes comes from a file a person wrote. |

## What you download

Twelve archives — two programs across six platforms:

| | |
|---|---|
| `fettle-1.0.0-<rid>` | the tool: CLI and MCP front ends, one file |
| `burler-1.0.0-<rid>` | the disclosure screen's model host — optional |

RIDs: `win-x64`, `win-arm64`, `linux-x64`, `linux-arm64`, `osx-x64`,
`osx-arm64`. Windows ships `.zip`; the rest `.tar.gz`, because the executable
bit only survives a tar.

Each archive carries the binary, `NOTICE` and `LICENSE`. Nothing needs to be
installed alongside them: both are self-contained single files, so the target
machine needs no .NET and no checkout.

`burler` is a separate download on purpose. It is only wanted by somebody who
has switched the disclosure screen on, and folding it into `fettle`'s archive
would make every download pay for ONNX Runtime to get a feature most trees
never use. `fettle` looks for it beside itself, so unpack both into one
directory if you want both.

`fettle` and `burler` are versioned together and always will be. A `burler`
from a different release is a wire-format gamble nobody signed up for.

## Getting started

1. Put `fettle` on `PATH`.
2. `fettle setup` writes the client registration, or write `.fettler.json`
   yourself — it is the file that says which trees exist and what may be done
   in each.
3. `fettle roots` says what it can see. `fettle doctor` says what on the
   machine still lets the boundary be gone round.

Nothing is granted by default that does not have to be. `execute` in
particular is never granted anywhere unless a person writes it down.
