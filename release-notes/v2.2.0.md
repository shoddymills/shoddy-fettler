## Fixed

- **A large answer was saved to a file instead of reaching the
  assistant.** 2.1.0 capped answers at 40,000 characters of text, counted
  before the text went into JSON. In JSON every quote, backslash and
  newline is escaped, and the field names count too, so an answer under
  the cap could arrive well over it. Claude Code saves an answer past
  50,000 characters to a file and shows the model a pointer instead, and
  did so with a 57 KB read. Every answer from `fettle` and `pick` now
  stops at 40,000 bytes of what is actually sent, and a refusal at
  10,000, under the size at which Claude Code cuts a long error. The
  terminal and `--json` stop at the same place. Every tool declares the
  ceiling to the client as `anthropic/maxResultSizeChars`. A last check
  replaces any answer still over the ceiling with a refusal that names
  its size, so an oversized answer is never sent.
- **A long line was served whole.** A minified file or a saved tool
  result is one enormous line, and `read` always served the first line
  whatever it cost. It now comes in pieces, and `next` gives `from` and
  `column` for the rest. A long line after short ones is not cut: the
  answer stops before it. A `search` hit in a long line is the match and
  200 characters either side, and `clipped`, `text_from_column` and
  `line_length` say where it sits. Context lines are cut to the same
  columns.
- **A list that was cut gave no way to the rest.** `find`, `search` and
  a `replace` dry run now stop at a whole entry and give `next`. Pass it
  back as `--after` (`after` over MCP). `pick objects` and `pick
  describe` page the same way, and each page of a `describe` carries the
  hash of the whole shape. `edit`, `batch`, `copy`, `tasks` and a
  `replace` that writes list what fits and count the rest in
  `plan_omitted`, `files_omitted`, `operations_omitted`,
  `links_skipped_omitted` or `tasks_omitted`. The totals stay exact.
  `pick select` stops at the last whole row that fits, and refuses a
  single row too wide for any answer, saying to select fewer columns or
  a substring.
- **A read of several images sent all of them.** One call now sends one
  image, and none over 5 MB. Another image in the same call answers its
  facts and says, in `withheld`, why its bytes stayed behind.
- **An answer was marked as an error by its exit code.** `doctor` exits
  1 or 2 when it finds something, so over MCP its report was marked as an
  error, and Claude Code cut it to its first and last parts, which left
  JSON that did not parse. An answer is now an error only when the
  operation did not do what was asked: a refusal, or a `batch` that
  stopped early. Exit codes are unchanged. A `batch` that stopped early
  now answers with `ok` false, an `outcome` and a `message`, like any
  refusal, and always shows the operation that failed.
- **`--count` stopped counting at `--limit`.** It counted the hits it
  would have served. It now counts every matching line.
- **`--files-only` listed hits, not files.** Its JSON answer was the
  `hits` list with the text left out, one entry per matching line, so a
  file with 300 hits filled the list and the limit. It now names each
  file once, with how many lines in it matched, in `matched_files`, and
  `--limit` counts files. The terminal prints `PATH  N`.
- **Input that was not what a verb takes was read as a default.** Over
  MCP, an argument a tool does not take was dropped, so `find` given
  `glob` for `pattern` listed the whole tree. In an edit script, a
  `replace` with no `with` deleted what it matched, and on the command
  line so did `--replace` without `--with`. A batch `write` with no
  `text` wrote an empty file. A whole-number flag given something else,
  such as `--limit abc`, used its default. Each of these is now refused
  before anything runs, and the refusal shows what is taken. That covers
  `fettle` and `pick`, over MCP and on the command line. Every operation
  in a batch is checked before the first one runs. To delete matched
  text, write `"with":""`, or `--with=` on the command line.
- **`setup tools` could drop the guardrails paragraph.** Re-run on a
  project where `setup guardrails` had written the instruction block, it
  kept the block only when the tools paragraph matched its own words
  exactly. After an upgrade that changed those words, it rewrote the
  block as tools only. It now keeps the guardrails paragraph and brings
  both up to date. The same command left an existing VS Code agent file
  alone, so its instructions never updated. It now rewrites it at the
  level the file already has, and never widens it.
- **`fettle --version` inside a tree printed the levels line first.** A
  script reading the first line got the levels. It now prints the
  version alone.
- **`run` kept terminal colour codes.** Each one is six bytes in JSON and
  tells a model nothing, and a coloured build log spent a third of its
  room on them. They are removed.
- **`pick` escaped every accented letter in its JSON answer** to a
  six-byte sequence, which made a column of names up to six times its
  size. It now writes them as they are, as `fettle` does.

## New

- **Hints.** Over MCP, a call that shows a missed batch or a missed
  hand-off gets a second text part starting `hint:`. That covers single-path
  `read` calls, single-pattern `search` calls and single file operations sent
  one after another, repeated `edit` calls to one file, an `edit` with no
  `expect` on a file read earlier, a repeated read of unchanged lines, a
  short read around the hit of the search just before it, the same
  refusal twice, and a path no tree covers. The answer itself is
  unchanged. `pick` hints on a repeated refusal. The command line never
  hints.
- **`{a,b}` in a glob**, one level deep: `**/*.{cs,md}` matches what
  `**/*.cs` or `**/*.md` matches. Brackets, a leading `!`, and nested or
  unbalanced braces are still refused with exit `2`.
- **`read --column N`** starts the first line part way along, for the
  rest of a long line.
- **`--after NEXT`** on `find`, `search`, a `replace` dry run, `pick
  objects` and `pick describe`. The terminal quotes the value when a
  shell would split it.
- **The install scripts take a version.** `fettler-install.sh 2.2.0`
  and `fettler-install.ps1 2.2.0` stamp the build with it and check that
  the installed binary reports it.
- **The instructions say more.** The instruction block, the VS Code
  agent file and the server instructions now say to do several things in
  one call, to feed each answer into the next, that every answer stops
  at 40,000 bytes and gives `next`, and that a subagent works under the
  same boundary. Run `fettle setup tools CLIENT` again to update an
  existing block or agent file.
